Tech stack · siem-poc · 2026-10-24

Tech stack: มีอะไรรันอยู่บ้าง และแต่ละตัวทำหน้าที่อะไร

ชื่อกล่องในแผนภาพคือชื่อ service ที่เห็นใน Docker Desktop ตรงตัว กล่องย่อยด้านในคือ image และ version ที่ใช้ ตัวอักษรสีน้ำเงินใต้กล่องคือ port ที่เปิดออกมานอก Docker

1 · docker-compose.yml · รันบนเครื่องคุณ

POC stack: 8 containers, ใจกลางคือ Graylog

docker compose up -d สร้าง 8 containers ใน network เดียวกัน มีแค่ 3 ตัวที่เป็น SIEM จริง (graylog, opensearch, mongodb) อีก 5 ตัวมีไว้ให้ POC ทดสอบได้โดยไม่ต้องมีอุปกรณ์จริง: จำลอง log เข้า, จำลองปลายทาง alert ออก, และตั้งค่าให้อัตโนมัติ

container image สถานะปกติใน Docker Desktop ทำหน้าที่ port / volume
graylog graylog/graylog:7.1.11 Running ตัว SIEM เอง: รับ syslog, รัน pipeline แยก field และเติมบริบท (asset, zone, threat intel), เก็บเป็น stream, ประเมิน alert, แสดง dashboard และ REST API ที่ provisioner ใช้ตั้งค่า :9000 UI/API · :1514 udp/tcp · :6514 tls
graylog_data, graylog_journal, ./graylog/lookup, ./tls
opensearch opensearchproject/opensearch:2.19.5 Running ฐานข้อมูลเก็บ log จริงและทำ index ให้ค้นหาเร็ว Graylog เขียนลงที่นี่ทุก message ใช้ RAM มากที่สุด (heap 1 GB) ไม่เปิด port ออกนอก Docker opensearch_data
mongodb mongo:7.0 Running เก็บ "การตั้งค่า" ของ Graylog ทั้งหมด: input, stream, pipeline rule, alert, dashboard, user ไม่ได้เก็บ log ถ้า backup ตัวนี้ได้ก็กู้ config คืนได้ mongodb_data
provisioner python:3.12-alpine Exited (0) หลัง up ~1–2 นาที สคริปต์ตั้งค่าอัตโนมัติ: รอ Graylog พร้อมแล้วเรียก REST API สร้าง input, lookup table, pipeline, stream, event definition, notification, retention, user ถ้า Exited (1) แปลว่าตั้งค่าไม่สำเร็จ ดูด้วย docker compose logs provisioner ./graylog, ./provisioner (read-only)
generator python:3.12-alpine Running (เริ่มหลัง provisioner จบ) ตัวแทน OPNsense/switch/AP ในช่วง POC ยิง syslog รูปแบบเดียวกับอุปกรณ์จริงเข้า graylog:1514 ทุก 5 วินาที พร้อมสุ่ม scenario ที่ควรเกิด alert ปิดได้เมื่อมีเครื่องจริง ./generator (read-only)
mailpit axllent/mailpit:v1.31.4 Running SMTP server ปลอมที่รับอีเมลทุกฉบับแล้วโชว์ใน web UI ใช้ดูว่า alert e-mail หน้าตาเป็นอย่างไรโดยไม่ต้องต่อ mail server บริษัท production จะเปลี่ยนเป็น SMTP relay จริง :8025 UI · :1025 smtp (ภายใน)
webhook python:3.12-alpine Running HTTP server เล็ก ๆ รับ POST จาก Graylog เมื่อเกิด alert แล้วแสดง JSON ล่าสุด เป็นตัวแทนของ LINE OA, MS Teams หรือระบบ ticket ที่จะต่อจริงใน Phase 1 :8088 UI + POST /alert
tools python:3.12-alpine ไม่ปรากฏ จนกว่าจะ docker compose run --rm tools … container ชั่วคราวสำหรับงานตามสั่ง: รายงานรายเดือน (monthly_report.py), ตรวจ hash ไฟล์ archive (log_manifest.py), ตรวจความครบของ dashboard (viz_check.py) รันเสร็จแล้วถูกลบ ./tools (read-only), ./reports

3 ตัวที่เป็น SIEM จริง

  • graylog คือสมอง: รับ, แยก, เติมบริบท, แจ้งเตือน, แสดงผล
  • opensearch คือความจำระยะยาวของ log (ค้นหาได้)
  • mongodb คือความจำว่า Graylog ถูกตั้งค่าไว้อย่างไร
  • 3 ตัวนี้คือสิ่งที่จะ deploy จริงใน production ตัวอื่นไม่ไป

5 ตัวที่มีไว้เพื่อ POC

  • generator แทนอุปกรณ์จริงที่ยังไม่มี
  • mailpit และ webhook แทนปลายทาง alert ที่ยังไม่ต่อ
  • provisioner ทำให้ up ครั้งเดียวได้ระบบพร้อมใช้ ไม่ต้องคลิกตั้งค่าเอง
  • tools รวมสคริปต์งานประจำ รันเมื่อสั่งเท่านั้น

สิ่งที่ไม่ใช่ container แต่คือ "ของเรา"

  • graylog/pipeline/*.rule 50+ กฎ parse และ enrich ที่ provisioner โหลดเข้า Graylog
  • graylog/lookup/*.csv ตาราง asset, zone, firewall rule, threat intel, หมวดเว็บ
  • tests/pipeline_cases.json log ตัวอย่างสำหรับทดสอบกฎ
  • image ทุกตัวเป็นของสาธารณะ ไม่มี custom build ความแตกต่างอยู่ที่ไฟล์เหล่านี้

2 · docker-compose.prod.yml · รันบน SIEM host ในออฟฟิศ

Production stack: เหลือ 5 containers บวกงานบน host

ตอน deploy จริง ตัวจำลองและตัวแทนทั้งหมดหายไป เหลือแกน SIEM เดิมที่ขึ้น HTTPS, bind port เฉพาะ IP ของเครื่อง, เพิ่ม truststore สำหรับ TLS ภายใน และย้ายงานประจำ (sync, manifest, report, backup) ไปเป็น systemd timer บน host แทน container tools

ส่วน POC (เครื่องคุณ) Production (SIEM host) ทำไม
graylog HTTP, port เปิดที่ 127.0.0.1 HTTPS ด้วย cert จาก tls/, port เปิดเฉพาะ SIEM_HOST_IP, syslog ที่ 514/6514 อุปกรณ์จริงส่ง 514 เป็นค่า default และ UI ต้องเข้ารหัสเมื่อออกนอกเครื่อง
truststore ไม่มี container ครั้งเดียว สร้าง Java truststore ที่มี CA ของเรา ให้ Graylog เชื่อ HTTPS ของตัวเอง (provisioner เรียกผ่าน https://graylog:9000)
generator · mailpit · webhook มี ไม่มี มีอุปกรณ์จริงและ SMTP relay ของบริษัทแทน (webhook ปิดไว้จนกว่าจะเลือก LINE/Teams/ticket)
tools container ตามสั่ง systemd timer บน host เรียก deploy/siem-job.sh ที่รัน tools/*.py ด้วย python3 ของเครื่อง ต้องเข้าถึง share ของ Synology (archive, backup) และ API ของ OPNsense จาก host โดยตรง
firewall ไม่มี siem-firewall.service ใส่กฎ DOCKER-USER จำกัดต้นทางของแต่ละ port port ที่ Docker publish ข้าม UFW/firewalld จึงต้องจำกัดในชั้นของ Docker เอง
backup ไม่มี ทุกคืน: MongoDB dump + graylog/ + .env + tls/ + OPNsense config.xml ไปที่ BACKUP_DIR กู้ "การตั้งค่า" คืนได้ ส่วน log ระยะยาวอยู่ที่ archive บน Synology อยู่แล้ว

ถ้าจำแค่ประโยคเดียว: Graylog คือ SIEM, OpenSearch คือที่เก็บ log, MongoDB คือที่เก็บการตั้งค่า ที่เหลือใน Docker Desktop คือนั่งร้านของ POC ที่จะถอดออกเมื่อขึ้นระบบจริง
